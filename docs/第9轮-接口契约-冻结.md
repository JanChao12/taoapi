## 1. 配置文件（`internal/config`）

路径：`%USERPROFILE%\.wbapi\config.json`

```json
{
  "version": 1,
  "apiKey": "key",
  "port": 8787,
  "autoCheckin": false,
  "autoStart": false,
  "aliases": { "dsf": "workbuddy/deepseek-v4.1-flash" }
}
```

> 🔴 **2026-10-05 委托人明确修正（覆盖早先版本，勿再改回）**：
> - **默认 key 统一为字面量 `"key"`** —— 不用随机值、也不用 `"1"`。
>   Codex 曾建议随机值，被委托人否决：自用工具、只监听回环，固定值便于记忆与首次接入。
>   面板仍提供「生成随机密钥」按钮供主动升级。
> - **`autoCheckin` 默认 `false`** —— 委托人明确"自动签到默认关"。
>   早期写的"默认开启"已作废。

**规则（逐条都有理由，实现必须遵守）**：

1. **host 不可配** —— 只能配 `port`；监听地址恒为 `127.0.0.1`。
   *理由（Codex）*：允许自由编辑 addr 时，默认 key 很容易因误配而暴露到公网。
2. **`apiKey` 首启用 `crypto/rand` 随机生成**（32 位十六进制）。
   *理由（Codex）*：固定默认值 `local` 公开可猜，等于没有保护。
   ≥64 字节熵。生成后写盘。
3. **`apiKey` 允许为空**（委托人明确要求）。空 = 不校验，但面板必须**明确警示**。
4. **`port` 范围 1–65535，且 <1024 拒绝**（避免需要管理员权限的端口）。
   保存后需**重启生效**（确认过的委托人选择：提示 + 一键重启）。
5. **`autoCheckin` 默认 `false`**（🔴 委托人 2026-10-05 明确修正），`autoStart` 默认 `false`。
6. **原子写**：复用 `internal/storage` 的临时文件 + rename 语义。
7. **配置损坏时**：不 panic、不覆盖。回退到默认值并把原文件重命名为
   `config.json.corrupt-<时间戳>`，在 `/status` 与日志中报告。**绝不静默丢弃用户配置。**
8. **文件权限**：`apiKey` 是本地 bearer 凭据，**不得进日志**（Codex 要求）。

**优先级（Codex 明确指出，否则 `--addr` 会覆盖持久化端口）**：
`命令行 flag` > `配置文件` > `内置默认`。

## 2. 鉴权（`internal/app`）

- **`/v1/*` 必须校验**：`apiKey` 非空时，要求 `Authorization: Bearer <key>`；
  不匹配返回 **401** + OpenAI 风格错误体。`apiKey` 为空则放行。
- **面板与本地管理接口（`/panel/*`、`/api/*`、`/status`、`/healthz`）不校验**。
  *理由*：只监听 127.0.0.1，且面板要能在未设 key 时打开；这是自用工具的既定边界。
- **常量时间比较**（`crypto/subtle.ConstantTimeCompare`），不用 `==`。

## 3. 设置 API（`internal/app/settings*.go`）

### `GET /api/settings`
**绝不回传明文 apiKey。** 返回：

```json
{
  "apiKeySet": true,
  "apiKeyHint": "a1b2…",          // 仅前 4 位 + 省略号，用于识别
  "port": 8787,
  "autoCheckin": true,
  "autoStart": false,
  "aliases": {"dsf": "workbuddy/deepseek-v4.1-flash"},
  "listenAddr": "127.0.0.1:8787",
  "restartRequired": false,
  "configCorrupt": false,
  "dataDir": "C:\\Users\\...\\.wbapi"
}
```

### `PATCH /api/settings`
请求体（**字段缺失 = 未修改**，这是 Codex 要求的区分）：

```json
{
  "apiKey": "newkey",        // 设置新值
  "apiKeyClear": true,       // 明确清空（与"未修改"区分）
  "port": 8888,
  "autoCheckin": false,
  "autoStart": true,
  "aliases": {"dsf": "workbuddy/deepseek-v4.1-flash"}
}
```

- 同时给 `apiKey` 与 `apiKeyClear` → **400**（语义冲突）。
- 保存成功后返回与 GET 相同的结构体。
- **保存成功后原子替换内存快照**，key/alias/开关**热生效**；端口只标记 `restartRequired`。
- `aliases` 的**合法性与循环校验由 router 层负责**（见 §4），本层只做存储。

### `POST /api/settings/restart`
一键重启（确认过的委托人选择）。实现方式：由 serve 自行重新拉起进程后退出。
⚠️ 必须**先确保新进程能起来**再退，否则会把用户的服务弄没（失败则返回 500 并保持运行）。

## 4. 映射表 / 别名（子智能体 A，`internal/router`）

**范围（Codex 否决了"顺带生成 DSH 配置"，本轮不做）**：只做服务端别名。

在 `router` 现有接口上**新增**：

```go
// SetAliases 原子替换别名表。返回错误表示别名表非法（不落盘、不生效）。
func (r *Router) SetAliases(m map[string]string) error

// Aliases 返回当前别名表的副本。
func (r *Router) Aliases() map[string]string
```

**校验规则（必须逐条实现 + 测试）**：
1. 别名 key 非空、**不得含 `/`**（避免与 `workbuddy/` 前缀混淆）、长度 ≤64。
2. 目标必须能被现有 `Resolve` 解析成功（即确实是 `workbuddy/xxx` 这类有效模型）。
3. **禁止自映射**（`a → a`）。
4. **禁止循环**（`a → b`, `b → a`）；只允许**一层**解析：
   解析别名得到目标后，**不再对目标做二次别名解析**。
5. **大小写敏感**（与模型 ID 一致）。

**`Resolve` 的行为**：
- 先用别名表查；命中则用其目标；否则按现有 `workbuddy/` 前缀逻辑。
- `Router.Models()` **包含别名条目**（Codex：否则客户端先查 `/v1/models` 会拒绝调用）。
  别名的 `id` 用别名本身，`owned_by` 或扩展字段标明它指向的真实模型。
- **统计要同时记录请求模型名与解析后的模型**（供用量页区分）。

## 5. 用量写入（我自己做）

- 位置：拿到上游**最终 usage** 之后。**同步 `Append`**（每请求一次，不影响流式首字节）。
- **不伪造 usage**：客户端断开且未收到最终 usage → **不写 token 数**；
  如需成功率，另写一条 `status=client_disconnected`、`usageKnown=false` 的事件。
- **`Append` 失败不得把已成功的对话变成 500**（只记录错误日志）。
- **写入加锁**，避免 JSONL 交错。
- 事件字段补 `requestID` / `status` / `usageKnown`，防重复统计。
- 按**本地日**切分（与签到 `todayCN()` 口径一致）。

## 6. 自动签到（我自己做）

- 🔴 **默认关闭**（委托人 2026-10-05 明确修正；早先写的"默认开启"已作废）。
  用户需在设置页主动开启。
- **开关关闭时不得启动任何调度**（连 ready 钩子都不注册）。
- **触发点改为「账号存储加载完成」的 ready 事件**，不再是固定 15 秒
  *理由（Codex）*：固定延时可能撞上账号/额度刷新，且无账号时会白发请求。
- **无账号时不发任何上游请求**，并在面板显示「未执行（无账号）」。
- 语义（确认过的委托人选择）：**启动时调度全部账号，当天已成功的跳过**（本地判断，
  不发请求）；**失败的允许本次重试一次**。
- 串行或有限并发 + **小抖动**，避免多账号请求突刺。
- **防并发**：手动签到与自动签到不得同时操作同一账号。
- **开关关闭 → 立即停止后续调度**，不是"等下次启动"。
- 设置页与运行状态显示：**已启用/已停用、上次触发时间、结果**。

## 7. 开机自启（子智能体 C，`internal/autostart`）

机制（确认过的委托人选择）：**注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`**

```go
package autostart

// Enable 注册开机自启。幂等：重复调用不产生重复项。
func Enable(exePath string, args []string) error
// Disable 取消开机自启。幂等：本来就没有也算成功。
func Disable() error
// Enabled 查询当前是否已启用（读注册表实际值，不读配置文件）。
func Enabled() (bool, error)
```

**要求**：
- 用 `golang.org/x/sys/windows/registry`？**不行 —— 零第三方依赖**
  → 用 `syscall` 直接调 `advapi32`（本项目 DPAPI 已是此模式，照抄 `storage/dpapi_windows.go`）。
- 值名固定 `wbapi`；值数据为 `"<exe绝对路径>" serve`（路径含空格要正确加引号）。
- **非 Windows 平台**：提供占位实现（返回明确错误，不静默成功），
  与 `storage/dpapi_other.go` 同一风格。
- 幂等性、路径引号、Disable 后 Enabled 为 false —— **都要有测试**。
  （读注册表的集成测试可用 `t.Skip` 保护，但纯逻辑如引号拼接必须测。）
