# 资源限额与验收基线

> 数值经双方确认（DSH × Codex，2026-10-04）。**全部可配置**，并写入压力测试。

---

## 一、运行时限额

| 项目 | 初始值 | 说明 |
|---|---:|---|
| **最大并发流** | **8** | 适合单用户；超限返回 **429**，**不无限创建 goroutine/连接** |
| **建连超时** | **10 秒** | `Transport.DialContext` |
| **响应头超时** | **30 秒** | `Transport.ResponseHeaderTimeout` |
| **SSE 单次读取空闲超时** | **120 秒** | ⚠️ **不是总请求超时** |
| **请求体上限** | **8 MiB** | 大上下文/工具调用需要；仍可拒绝超大图片 |
| **JSONL 单文件上限** | **16 MiB 或按日切换**（先到者触发） | 轮转为带序号文件，原子关闭并保留历史 |

### ⚠️ 最容易搞错的一条：SSE 超时

**绝对不能用 `http.Client.Timeout = 120s`** —— 那是**整个请求**的总超时，
会把长思考流（实测 max 档单次可达 95 秒，且未来可能更长）**中途杀掉**。

**正确做法**：
- 用 `Transport` 配置**建连**和**响应头**超时
- 为**每条流**单独设 **idle timer**（两次读取之间超过 120 秒才算超时）
- 超时后关闭上游连接并返回**可诊断错误**（不是静默截断）

## 二、内存验收基线

| 指标 | 门槛 | 依据 |
|---|---|---|
| `serve` 预热后**空闲 30 分钟** RSS **P95** | **≤30 MB** | 同机实测：Go 19.27 MB（wild-work）、Python 18.73 MB |
| 事件追加后 | **无持续增长** | 有界缓存 + 按需流式查询 |
| 并发 4 个流 | 无异常增长 | 每流一个 goroutine 是预期行为 |

**报告口径**：
- **只报 RSS**（Working Set），**不报 VSS**（Go 官方文档明确说 VSS 判内存"通常没什么用"）
- 同时记录 `Private Working Set` 与 `Commit` 作为辅助
- **30 MB 是工程门槛，不是语言保证**

| # | 场景 | 预期 |

| 8 | **连续多轮请求** | RSS 无持续增长 |

## 四、验收标准（可证伪）

1. **断网构建**：删除所有上游 remote、设离线模块模式后，仍能 `go build`
2. **`/v1/models`**：ID 全部带 `workbuddy/` 前缀；**不硬编码数量**（上游实测 31 个，中间层只显示 17 个）
3. **安全**：fake upstream 收到 `X-Refresh-Token`、缺身份头、或 `stream != true` → **测试立即失败**
4. **流式**：能收到 role / reasoning_content×N / content / usage / `[DONE]`
5. **非流式**：同一上游流完整聚合；**不因 41 个 reasoning 分片而丢 content**
6. **档位**：3 个模型各一组 fixture；**deepseek 不传字段必须识别为 off**，不能冒充 high
7. **DSH**：按配置连接后档位菜单出现；至少一次 high 与一次选档能在上游样本中观察到变化
8. **内存**：预热后空闲 RSS P95 ≤30 MB；场景 1–8 全部通过且无无界增长
